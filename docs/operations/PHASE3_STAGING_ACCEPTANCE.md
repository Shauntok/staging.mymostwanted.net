This checklist is for an isolated MMWR Staging project with synthetic accounts and records. It is preparation only: do not apply migrations, configure secrets, turn on feature flags, send mail, or modify Production until the project and change window are explicitly authorized.

- Confirm the Supabase project is MMWR Staging, uses synthetic data, and is not connected to Production credentials, Storage, SMTP recipients, or public DNS.
- Check pending migration order and record the current migration version. Both the owner IP Data API guard and the single-header correction refuse to replace an unknown `authenticator` `pgrst.db_pre_request` hook; inspect and deliberately chain any existing hook before applying or retrying either migration.
