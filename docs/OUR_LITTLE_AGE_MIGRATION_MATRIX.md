## Scope and decision rule

Only Our Little Age's `AGENTS.md`, `PROJECT_CONTEXT.md`, `HANDOFF.md`, `README.md`, `package.json`, selected application source, and schema/migration source were inspected. No environment files, secrets, backups, databases, production content, user data, private evidence, logs, or generated outputs were opened. Paths below are relative to the Our Little Age repository unless prefixed `MMWR:`. Its project documentation includes historical deployment claims; those claims are not live verification for this audit.

`reuse pattern` means the isolated idea may inform a new implementation; `adapt` means the workflow or model needs MMWR-specific changes; `rewrite` means the current implementation is unsuitable as code; `defer` means the MMWR feature remains outside V1; `do not use` rejects the identified behavior. None of these decisions authorizes copying source tables, credentials, Storage objects, or Production data. The MMWR authority is `MMWR:HANDOFF.md` and `MMWR:MASTER_PLAN.md`; every optional default-OFF feature stays OFF.

## Migration dependencies and approval gates

1. Define MMWR's post/subject/alias/evidence/tag/location/revision and visibility state machines before adapting search, tags, share, or reactions. Public queries must be scoped to approved, currently public material, and Emergency Hide must remove it from every public surface, cache, and index.
2. Define Owner/Admin RLS and server authorization, TOTP gate, internal evidence access audit, data retention, and deletion behavior before adapting moderation, reports, dashboards, or campaigns. Never reuse the source project's grants as an MMWR permissions matrix.
3. Resolve Malaysia boundary data/license, legal review, attachment limits, Telegram destination, and analytics/consent definitions in MMWR's own configuration plan. These are unresolved dependencies, not values to infer from the source.
4. Keep advertising, ad tracking, boost, comments, VIP, automatic translation, video, and drafts at their MMWR default OFF state. Source code existing or source documentation claiming a feature was deployed does not change MMWR approval or Production status.
